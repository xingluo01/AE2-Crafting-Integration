# 待办表编写规则

本规则只管 `docs/TODO.md` 一份文件。仓库里**只允许一份待办表**，根目录再建一份一律视为错误。

写作口径对齐 `CHANGELOG_STYLE.md`：一行一条、一句短话、只讲事实、不写成因与实现机制。差别是更新日志写「已经发生的变化」，待办表写「还没做完、可以验收的事」。

## 一、这份表是什么

- 下一轮动手的人（人或 AI 代理）的**工作清单**：打开就知道要做什么、什么算做完。
- 一条待办 = 一件能验收的事；做完即删，不勾 `[x]`、不留「已完成」段、不留归档。
- 不是开发日志、设计说明、测试报告、上游资料库，也不是发版清单。

## 二、该写什么

| 类型 | 收什么 | 落在哪一节 |
|---|---|---|
| 实机验证 | 代码已落地、只差上机，写清验什么与通过判据 | 待实机 |
| 功能待办 | 还没做的功能、还没接的适配 | 未开始 |
| 决策待办 | 「要不要做 / 怎么做」尚无结论，写清待定的是什么 | 未开始 |
| 阻塞条件 | 卡在上游或环境的**前置**，只写会影响下一轮做法的 | 对应条的「前置」子行 |
| 暂缓 | 明确不做但留个由头的，只写阻塞本身 | 暂缓 |

一句话判据：**这条描述的「要做的事」现在还没做吗？** 已经做了，或压根不是一件要做的事，就不写。

## 三、不该写什么

- **已完成的工作**：实现细节、改了哪个类、跑了哪些测试与编译、提交记录 → `CHANGELOG.md` 与 git 历史。
- **已完成条目的勾选框** `[x]`、「已修 / 已补 / 本轮已完成」段、归档段落。
- **实现原理与成因复盘**：为什么这么设计、「此前…现在…」对照、方案取舍 → 代码注释或 `ARCHITECTURE.md`。
- **上游资料与外部噪音**：上游源码事实基线、版本变动、第三方模组崩溃 → 对应集成注释。
- **发版动作与对外文案** → `RELEASE.md` 与对应交付文档。
- 单条里塞多件事、把判据写成散文、重复条目。

## 四、结构

- 首行标题，随后一段 `>` 引用：本表口径、状态图例、优先级、指向本规则与归档去处。
- 状态分节固定顺序：`## 一、待实机` → `## 二、未开始` → `## 三、暂缓`；出现「进行中」时插在最前并顺延编号。**没内容的小节整节不写**。
- 末尾固定 `## 归档索引`（不带状态编号）：指向 `CHANGELOG.md`、git 历史、`ARCHITECTURE.md`、`RELEASE.md` 与本规则。
- 功能块用 `### <功能名> — P<n>`，P1 最高、P3 最低。**不要**用数字占位编号，标题本身就是标识。
- 功能块按 P 值升序排；同一功能既有实机项又有待补项，按状态拆成两个块。

## 五、工作陈述格式（硬约束）

每条主行固定：

```
- ⬜ <动词>**<对象>**：<一句工作陈述>。
```

- **一行一条**：不换行、不套多层子列表；主行与子行各 ≤135 字节。
- **句首是动作动词**：待实机用 `验证` / `确认`；未开始用 `新增` / `补齐` / `支持` / `调整` / `核对`。
- **加粗只给被操作的对象**，一条一次。
- **只讲事实**：不写成因、不写实现机制、不写「此前…现在…」对照、不写副作用。
- 标点全角，引号用「」，代码 / 类名 / 文件名 / 键名用反引号；不贴日志、截图、链接。
- 图例：`⬜` = 还没做完，`⏸` = 暂缓。状态由所在小节决定，主行里不要再写状态词。

可选子行（各一行、最多两条）：

```
  - 判据：<什么算通过 / 什么算做完>。
  - 前置：<解除阻塞的条件>。
```

判据只写结果，不写推导；前置只写条件，不写背景。

**禁止自由前缀**：`- 背景：` / `- 已有证据：` / `- 事实基线：` / `- 来源：` / `- 维护：` / `- 约束：` 一律不用。

## 六、正反例

正：

```
- ⬜ 验证**9x9 网格的空槽不参与匹配**：只放 3x3 原料时按 3x3 配方产出。
  - 判据：9x9 配方匹配器对空格返回 `null` 而不是空配方。
```

反（一条里塞了实现原理、测试结论与更新日志取舍）：

```
- ⬜ 实机：9x9 网格不应把空格当原料。`PatternMatcher` 内部是 81 格稀疏数组……
  这条已被单测覆盖，实机再看一次。
```

## 七、自检

- [ ] 全仓只有 `docs/TODO.md` 一份待办表；没有根目录 `TODO.md`。
- [ ] 没有 `[x]`、没有「已完成 / 已修 / 已补」条目，没有归档段落。
- [ ] 每条主行是一行、一件可验收的事、句首动词 + 加粗对象一次、≤135 字节。
- [ ] 没有背景 / 证据 / 基线 / 来源 / 维护等自由前缀。
- [ ] 没有重复条目；单条里没有塞第二件事。
- [ ] 分节顺序正确、无空小节、功能块标题无占位数字。
- [ ] 头部引用指向本规则；末尾归档索引齐全。
