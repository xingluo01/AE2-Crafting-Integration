# 更新日志编辑规则

本规则管两份文件：

| 文件 | 职责 | CI |
|---|---|---|
| `CHANGELOG_UNRELEASED.md`（根目录） | **未发布的累计调整**：开发期唯一要动的文件，它就是下一个版本发布说明的草稿 | 不读 |
| `CHANGELOG.md`（根目录） | **已发布内容的留档**：版本段会被 CI 取出，作为 GitHub Release 说明，并同时送 Modrinth 与 CurseForge | 读（发布工作流迁入后生效） |

改格式前先看 `.github/workflows/release.yml`（当前尚未迁入，见 `RELEASE.md`）。体例对齐 NEO ECO AE Extension 的更新日志：小节固定、一行一条、只讲事实。

## 一、结构（CI 硬约束）

### 未发布文件

- 首行 `# 未发布改动`，随后一行说明它跟 `CHANGELOG.md` 的关系（发版时整段并入）。
- 唯一的段落标题是 `## [未发布]`，不带日期。小节只能用 `###`，名与顺序同第二节。
- 本文件不被 CI 读取，格式瑕疵不会影响本次发布；但它是发版文案的唯一来源，小节名与顺序仍要与留档文件一致。

### 留档文件

- 首行 `# 更新日志`。
- 版本段一律 `## [<版本>] - <YYYY-MM-DD>`：版本号不带 `v` 前缀，日期是发布当天。
- **`## [` 是段落边界**：CI 从版本段标题的下一行开始取，遇到下一个行首 `## [` 停止。正文里不许出现行首 `## [`。
- 版本段的标题行不进正文；发布页首行那个标题由 CI 注入（见第五节），别在文件里手写。
- 取不到版本段时 CI 不报错地退回按 commit 主题拼接（日志里留一行 `changelog source:`）。能不能取到只看一件事：标题里要有精确的 `[<版本>]`（版本号 = tag 去掉前导 `v`）。
- 留档文件里不再出现 `## [未发布]`：待发内容住在上面的文件里。

### 发版时（按顺序做完四步）

1. 把 `CHANGELOG_UNRELEASED.md` 里 `## [未发布]` 那一整段（含小节与条目）搬到 `CHANGELOG.md` 顶部，标题改成 `## [<版本>] - <YYYY-MM-DD>`（日期用当天）。
2. 把 `gradle.properties` 的 `mod_version` 改成同一个版本号：本地构建产物用它，CI 则用 `-Pmod_version=<tag 版本>` 覆盖。
3. 把 `CHANGELOG_UNRELEASED.md` 清回骨架：标题、说明、空的 `## [未发布]`。
4. 已发布的版本段此后不再增减条目（边界见第二节末）。

## 二、小节：固定六个，顺序固定（两份文件同一套）

| 序 | 小节 | 收什么 | 句首动词 |
|:--:|------|--------|----------|
| 1 | 新增 | 玩家此前拿不到的东西 | 新增 |
| 2 | 支持 | 接进了别的模组或格式 | 支持 |
| 3 | 改进 | 已有的东西变好 | 改进 |
| 4 | 修复 | 此前是错的 | 修复 |
| 5 | 调整与依赖 | 有意为之的改动与版本下限 | 调整 |
| 6 | 更正 | 这份文档历史段落里写错的描述 | 更正 |

- 没内容的小节整节不写。代码的错归「修复」，文档的错才归「更正」。
- 留档文件里已封版的段落是归档，**不再增减条目**：不补新条目、不删旧条目、不合并、不调整条目顺序，也不调整小节顺序、不改小节归属、不改版本标题的文字。只允许修正错别字、标点与格式瑕疵。
- 发现归档段落里的事实写错了（含日期写错），写进 `CHANGELOG_UNRELEASED.md` 的「更正」小节，不回头改历史。

## 三、条目

- **一行一条**：`- ` 开头，不换行、不套子列表。
- **一句短话，只讲事实**：多数条目 30 字上下，最长不超过 135 字节（约 45 汉字）。不写「此前…现在…」的对照，不写成因，不写副作用，不写实现机制。
- **只写上一已发布版本玩家能遇到的事**：同一版开发过程中自己引入又自己修掉的问题不写。
- **句首复用小节名当动词**：「新增…」「修复…」「改进…」「调整…」。抹掉首词后句子应仍成立。
- **加粗只给被改动的对象**，一条一次，加粗名词短语而非语气词。
- 行为边界压成一句跟在同一条里；细节写进游戏内指南或 `docs/`，不在更新日志里展开。
- 标点用全角，引号用「」，代码与文件名用反引号；不写 emoji、表格、截图、链接。

## 四、依赖下限的写法

放在「调整与依赖」末尾，句式固定：

```
- AE2 最低版本为 **19.2.19**
```

只列**本次发版变动的**硬线下限（`neoforge.mods.toml` 里进了 `versionRange` 的那些）。没变的不重复列。软依赖的建议版本写进条目正文。

## 五、发布页（CI 拼，不用手写）

- 正文首行由 CI 注入 `# AE2 Crafting Integration <版本> 更新日志`。
- GitHub Release 标题沿用 tag（`v0.1.0`）；CurseForge 的 display_name 用 `AE2 Crafting Integration <版本> [NeoForge 1.21.1]`。
- 发布说明不用 GitHub 自动生成的 notes：基线会被托管依赖分支带偏。

## 六、发版前自检

- [ ] `grep -c '^- ' CHANGELOG_UNRELEASED.md` 为 0：没漏搬的条目
- [ ] `git diff CHANGELOG.md` 只多出一段，且 `git diff CHANGELOG_UNRELEASED.md` 只少掉条目
- [ ] `grep -n '^## \[' CHANGELOG.md`：行首 `## [` 只出现在版本段标题，且没有 `## [未发布]`
- [ ] `grep -n '^## \[' CHANGELOG_UNRELEASED.md`：只有 `## [未发布]` 一行
- [ ] 小节名与顺序符合第二节；无空小节、无裸列表
- [ ] 每条目句首动词与小节一致；一行一条、只讲事实
- [ ] 变动的硬线下限已写进「调整与依赖」
- [ ] 发布后扫一眼标题行之后的第一行：是小节名，不是 commit 主题

## 七、正反例

正：

```
- 新增**9x9 通用分子装配室**
- 修复超过 **64 种原料**的配方被错误拦截，导致合成任务无法推进的问题
- 调整**样板编码终端**的 9x9 网格布局
```

反（一条里说了成因、症状、修法三件事，还有两个类名）：

```
- 修复**无线终端的 FE 充能**：此前那行 FE 能力登记挂在了游戏总线上（`@EventBusSubscriber` 的 `bus` 默认值是 `GAME`），而它订阅的是模组总线事件，于是那段从未执行——不报错、不警告，只表现为这三台在 FE 设备上充不上电；AE2 自家的充能器按 `IAEItemPowerStorage` 认，不受影响。现在由模组总线的构造器直接调用。
```

玩家只需要知道「无线终端在 FE 设备上充不上电，已修」：

```
- 修复**无线终端在 FE 设备上充不上电**的问题
```
